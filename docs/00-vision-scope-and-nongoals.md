# 00 · 愿景、范围与 Non-Goals

> 本文是整个项目的"边界文档"。任何后续设计/编码若与本文冲突，以本文为准（除非显式更新本文）。
> 遵循"先定边界、再写实现"的原则——本文不含任何实现代码。

---

## 1. 一句话定义

> **Sales Forecast Decision Copilot**：用多模型预测未来 4 周 sell-out，用库存约束生成 sell-in 建议，
> 用促销/新品模块做场景模拟，用层级校准保证各级数字一致，用 Agent 把预测翻译成可执行建议，
> **并用 Forecast Value Add 持续证明它比现有人工流程更好。**

---

## 2. 我们真正要解决的问题

不是"预测得更准"这个抽象目标，而是让以下**具体决策**变得更好、更快、更可被追责：

1. 未来 4 周某 Country×Channel×SKU 大概卖多少（sell-out）？
2. 这周应该给渠道补多少货（sell-in）？补多了会压货吗？
3. 哪些 SKU 有缺货风险？哪些有压货风险？
4. 一个促销方案大概会带来什么结果？
5. 一个新品首 4 周该铺多少货？
6. 销售经理改了哪些预测、为什么、事后证明改得对不对？

**北极星指标：Forecast Value Add (FVA)** —— 相对现有人工/朴素流程的误差改进及其业务价值换算。
详见 `06-evaluation-trust-and-override-loop.md`。

---

## 3. 为什么是"决策系统"而不是"模型"

高层不信预测，根因通常不是模型不够先进，而是系统回答不了：
为什么这么预测 / 比人工好多少 / 哪里会缺货 / 哪里会压货 / 促销后会怎样 / 谁改了什么。

因此我们把"信任"当作一等公民来设计：**可解释（每个数字有来源）、可追责（override 有人有原因）、
可复盘（回测与 FVA 公开）、可证明（与现状对照）。** 模型只是达成上述目标的一个零件，可被替换。

---

## 4. 范围边界（In Scope）

| 维度 | v1 范围 |
| --- | --- |
| 预测对象 | sell-out（真实需求），并据此**推导** sell-in 建议 |
| 时间粒度 | 周（weekly） |
| 预测视野 | 未来 4 周（rolling 4-week horizon） |
| 输出 | 分位数预测 P10 / P50 / P90（不是单点） |
| 层级 | Region → Country → Channel → SKU，且各级数字相互一致 |
| 业务模块 | 库存/sell-in 建议、促销场景、新品 Analog（按路线图分期上线） |
| 决策定位 | **辅助决策（human-in-the-loop）**，人保留最终决定权 |

---

## 5. Non-Goals（明确不做——这一节和"做什么"同等重要）

写清楚不做什么，是管理高层预期、避免范围蔓延的关键。**v1 明确不做：**

1. **不做实时数据流 / 实时预测。** 周粒度、批处理足够。
2. **不做自动执行。** 系统**不**自动发货、不自动改预测、不自动上促销。所有动作由人确认。
3. **不替代计划员/销售。** 它是 copilot，不是 autopilot。
4. **不做严肃的因果促销 uplift 模型。** v1 的促销模拟是**相关性场景探索 + 规则护栏**，会显式标注不确定性，不声称因果。详见 `05`。
5. **不做复杂权限系统 / 审批工作流引擎。** 只做最小可用的 override 记录与审计。
6. **不做多租户 / 通用数据平台 / 通用 MLOps 平台。**
7. **不做竞品情报推断。** Agent 不得编造竞品、宏观或任何无数据支撑的因素。
8. **不在 v1 押注 Foundation Model。** TimesFM/Chronos 作为后期"挑战者"评估，不作为 v1 主预测器（理由见 `04` 与 `REVIEW`）。
9. **不追求 SKU 全量覆盖。** v1 聚焦少量高价值 SKU 把闭环跑通。

> Non-Goal 不等于"永远不做"，而是"不在当前阶段做、不让它分散信任建设的注意力"。
> 任何把 Non-Goal 移入 Scope 的提议，都应作为一次显式的边界变更来讨论。

---

## 6. 成功标准（Definition of Success）

v1 被视为成功，当且仅当：

1. 在试点国家，系统的 **FVA 为正**：误差显著低于现有人工/朴素 baseline（目标：相对 baseline 的 WAPE 改进 ≥ 用业务认可的幅度，具体阈值在 `09` 与干系人敲定）。
2. 高层能在一个页面看懂："比现状好多少、好在哪、风险在哪、谁改了什么"。
3. 至少一位区域/国家销售负责人愿意在真实决策中**参考**系统输出（而不仅是被动观看）。
4. 全流程**无数据泄漏**、回测协议被独立复核通过（见 `04`）。

> 注意：成功标准里没有"模型 WAPE < X%"这种孤立指标。
> 孤立的精度数字不构成信任，**相对现状的改进 + 可解释性 + 无泄漏**才构成信任。

---

## 7. 关键假设与风险（需在 `09` 中验证）

- **假设**：试点范围内有足够干净的历史 sell-out 数据。**这是头号风险**——若不成立，需启用 fallback（见 `03`/`09`）。
- **假设**：未来 4–8 周促销计划可作为 known future covariate 提供。
- **假设**：能拿到渠道库存（channel inventory）数据来支撑 sell-in 推导。
- **风险**：层级各级口径不一致（例如 Country 汇总 ≠ SKU 之和）会直接摧毁高层信任——由层级校准解决（见 `04`）。

# 对 OpenAI 原始方案的评审（决策记录）

> 本文记录：对 OpenAI 给出的方案，我们**同意什么、修改什么、为什么**。作为后续争议时的决策依据。
> 一句话结论：**原方案约 80% 是对的，核心框架（"做决策系统而非模型"）完全认同；
> 主要分歧在优先级——尤其是 Foundation Model 的地位、FVA 的权重、以及"先验证数据现实再动手"。**

---

## 1. 完全同意的部分（直接采纳）

| 原方案要点 | 评价 |
| --- | --- |
| "不该做一个预测模型，该做销售决策系统" | ✅ 最重要的判断，完全认同，作为全项目主轴 |
| 数据语义层 + 标准表结构（fact_*/dim_*/forecast_*） | ✅ 设计合理，几乎原样采纳（仅补门禁与 as-of 契约） |

## 2. 主要修改（分歧点 + 理由）

### 修改 1：Foundation Model（TimesFM/Chronos）从"核心"降级为"Phase 4 挑战者" 🔧
- **原方案**：把 TimesFM/Chronos 列入核心模型层，作为 ensemble 成员与对照。
- **改为**：v1 关键路径**不含** Foundation Model；它们作为后期挑战者拉进回测，若更优则自动获得 ensemble 权重。
- **理由**：
  1. **与信任目标相悖**——它们是黑盒，而 v1 的全部目的是可解释、可证明。
  2. **基础设施风险**——GPU、大模型下载、依赖地狱，让"给高层现场演示"更易翻车。
  3. **边际收益不确定**——在有价格/促销/库存外生变量的零售场景，调好的 LightGBM 往往已很强。
  4. **正确时机**——先用成熟组件把信任闭环跑通，再引入重型组件，不拿 v1 信誉去赌。
- 详见 `04 §2`。

### 修改 2：FVA 从第 11 项提升为北极星指标 🔧
- **原方案**：评估指标里有 FVA，但 WAPE 等并列、且整体放在靠后位置。
- **改为**：**FVA（相对现状的改进）是北极星**，是成功/上线/退出标准的核心；WAPE 等是支撑指标。
- **理由**：高层信的是"比你们现在好多少"，不是孤立的 WAPE 绝对值。FVA 才是信任的硬通货。
- 详见 `06 §1`、`00 §6`。

### 修改 3：把"评估/回测"前置为先决条件，并独立成层 🔧
- **原方案**：评估列在第 11 项，偏后台。
- **改为**：回测协议在写第一个模型**之前**锁定，评估骨架是架构中的一等公民层（`02`），且建议他人独立复核防泄漏。
- **理由**：没有可信回测协议，再多模型都是噪声；数据泄漏是"看着很美、上线全崩"的头号杀手。
- 详见 `04 §1`、`02`。

### 修改 4：新增"数据现实边界"为头号阻塞问题 🔧
- **原方案**：默认有 sell-out 数据，直接进入 sell-out→sell-in。
- **改为**：把"是否有干净 sell-out / 库存数据"列为 🔴 阻塞性开放问题，并给出情形 A/B/C 与 fallback。
- **理由**：消费电子常只有 sell-in，没有干净 sell-out。前提不成立时整套需求侧逻辑要降级，必须先确认。
- 详见 `03 §1`、`09 A1/A2`。

### 修改 5：促销模拟器明确标注"相关性而非因果" 🔧
- **原方案**：Promotion Simulator 列为页面，且把"严肃因果 uplift"列为 Non-Goal（这点对）；但页面表述容易被误读为因果 what-if。
- **改为**：v1 显式声明它是相关性场景探索 + 规则护栏，每个场景带不确定性区间与类比样本量，UI 明示"非因果保证"。
- **理由**：过度承诺因果，一次"模拟说涨结果没涨"就会击穿信任。宁可少承诺。
- 详见 `05 §3`。

### 修改 6：信任策略显式化为 Shadow Mode 试点 🔧（原方案隐含但未点明）
- **改为**：上线前先在 1 个友好国家**并行影子运行 6–8 周、不改任何决策**，用 FVA 对照报告去汇报高层。
- **理由**：这是赢得高层信任的**最低风险路径**——零风险、用事实说话、把销售变盟友。
- 详见 `01 §3`。

### 修改 7：路线图按"信任里程碑"而非"功能完成度"分期 🔧
- **改为**：P0 能测量好坏 → P1 证明更准且数字一致 → P2 变成行动 + override → P3 场景/新品 → P4 挑战者/解释力。
- **理由**：信任逐级累加，不能跳级；把黑盒/重型组件放最后，保护早期信誉。
- 详见 `08`。

## 3. 强化（认同方向，加大力度）

- **Override 闭环**：原方案有表，我们升级为"信任引擎"——季度末做 override 的 FVA 分析（谁改得对/错），把销售从"被取代"变为"被度量的盟友"。`06 §4`
- **Agent 护栏**：原方案"只解释不决策"基础上，加硬性规则——**Agent 不做任何运算、输出的每个数字都必须来自结构化事实、每条结论带字段级来源**。`07 §3`
- **Non-Goals 显式成文**：原方案 MVP 有"先不做"，我们把它升级为正式的 Non-Goals 章节并加入项目边界纪律（管理预期=半个买入）。`00 §5`

---

## 4. 没有改变的判断

- 选型、表结构、特征工程清单、MVP 数据范围、5 页 Dashboard 结构——基本原样采纳。
  **本项目与原方案的差异不在"用什么技术"，而在"优先级、边界、和如何赢得信任"。**

---

## 5. 一句话总结

> 原方案是一份优秀的技术方案。我们把它从"一份技术方案"调整为"一份以赢得高层信任为第一目标的产品方案"：
> **同样的零件，重排优先级——先证明能测量、再证明更优、把好预测变成行动、最后才碰黑盒；
> 全程用 FVA 说话、用 override 把人变盟友、用 shadow mode 零风险落地。**

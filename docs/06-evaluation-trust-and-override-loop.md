## 1. 北极星：Forecast Value Add (FVA)

> 高层不会因为"WAPE 17%"而信任你。他们会因为"比你们现在的做法好 11 个点、约等于省下 $X"而信任你。

**FVA = 现有流程误差 − 本系统误差**（误差用 WAPE / Weighted WAPE），并尽量换算成业务价值：

```text
FVA(WAPE)   = WAPE(现状/人工/朴素) − WAPE(本系统)
FVA(价值)   ≈ 因更准而避免的 (缺货损失 + 压货占用 + 加急调拨)
```

- **必须有正向 FVA 才考虑上线**（见 `00 §6` 成功标准、`01 §3` 退出标准）。
- FVA 要分层、分场景报告（哪个国家/渠道/SKU 改进最大，促销期 vs 平销期）。
- FVA 看板是 Executive Overview 的信任核心。

## 2. 指标体系（每个指标都对应一个业务问题）

| 指标 | 回答什么业务问题 | v1 必报 |
| --- | --- | --- |
| WAPE | 整体准不准（销售最易理解） | ✅ |
| Weighted WAPE | 高销量 SKU 加权后准不准 | ✅ |
| Bias | 长期系统性高估还是低估 | ✅ |
| P90 Coverage | 高需求风险是否被分位数覆盖（校准） | ✅ |
| **Forecast Value Add** | **比人工/朴素强多少（北极星）** | ✅ |
| Stockout Hit Rate | 缺货预警是否有效命中 | ⬜ 库存模块上线后 |
| Overstock Alert Precision | 压货预警准不准 | ⬜ 库存模块上线后 |

> 指标按 horizon（h=1..4）和场景分段报告，不要只给一个总平均（平均会掩盖促销期/新品的差表现）。

## 4. Override 审计闭环（把怀疑者变成盟友的机制）

> 这是让销售从"AI 要取代我"转向"AI + 我的判断、并且被度量"的关键产品能力。

### 4.1 流程
```text
系统产出 P50 (original_p50)
  → 销售/计划员可修改 (override_p50)，必须填 override_reason 和 owner
  → 写入 forecast_override 表 (见 03)
  → 季度末做 override FVA 分析:
       谁的 override 提升了准确度? 谁的拉低了?
       哪类原因 (促销/竞品/渠道动作) 的 override 更靠谱?
```

### 4.2 为什么这是信任机制而非负担
- **可追责**：每次修改有人、有原因、有时间，不再是"预测莫名其妙变了"。
- **可复盘**：事后能客观说明"这次人工调整是对的/错的"，对事不对人地积累经验。
- **保护销售**：当系统错而销售对时，override 记录为销售背书；反之也能温和地校准过度自信的手动调整。
- **持续学习**：高频且事后被证明正确的 override 模式，是下一轮特征工程的线索（例如某种渠道动作系统总没捕捉到）。

> 设计纪律：override **永远不被系统静默覆盖**。系统可以提示"你的这次调整历史上往往偏乐观"，但最终值由人决定。

## 5. 评估的工程化（不是 notebook，是流水线）

- 回测、指标、FVA 全部由 `forecast_run` 自动产出并入库，可在 Dashboard 直接看，不依赖手动跑 notebook。
- 每次 run 可复现（数据快照 + 模型版本 + 随机种子，见 `02 §4`）。
- 回测协议（`04 §1`）锁定后不可随意更改；若更改需记录原因（避免"调协议刷指标"）。
- 强烈建议：让一位非作者**独立复核回测代码是否存在泄漏**（`04 §1.2` 清单），复核通过再对高层汇报数字。

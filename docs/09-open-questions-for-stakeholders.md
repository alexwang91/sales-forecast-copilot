# 09 · 编码前必须敲定的边界问题

> 遵循"先定边界、再写实现"。本文是进入 Phase 0 编码前要和干系人（数据/销售/供应链/高层）确认的清单。
> **带 🔴 的是阻塞性问题——未确认前不应开始编码。**

---

## A. 数据可得性（最关键）

- 🔴 **A1. 是否有干净的历史 sell-out 数据？覆盖哪些国家/渠道、多长历史？**
  决定走 `03 §1` 的情形 A / B / C。这是整个方案能否成立的前提。
- 🔴 **A2. 是否有渠道库存（channel inventory）历史数据？**
  没有库存数据，sell-in 推导（`05`）和库存风险模块无法做，且情形 C 的 sell-out 估算也做不了。
- **A3. 未来 4–8 周的促销计划是否结构化可得**（折扣率、促销类型、起止周）？
  决定 known future covariate 白名单（`03 §4`）能放多少。
- **A4. 价格（retail/dealer）历史与未来计划是否可得？**
- **A5. 产品主数据（launch/eol/predecessor/successor、category/series/price_tier）是否齐全？**
  新品 Analog（`05 §4`）强依赖 predecessor 与相似维度。
- **A6. 历史数据的最小可用长度？** 至少要覆盖一个完整季节周期 + 若干促销周期，回测才有意义（`04 §1`）。

## B. 现状基线（FVA 的前提）

- 🔴 **B1. 现在的预测是谁做的、怎么做的？**（销售拍脑袋 / Excel / 去年同期 / 移动平均？）
  没有现状定义就没有 FVA 对照（`06 §1`）。
- **B2. 现有人工预测的历史值是否被留存？** 若有，可直接做"人工 vs 系统"FVA；若无，只能先和朴素基线比。
- **B3. 现有流程的主要痛点是什么？**（滞后 / 口径不一致 / 无法复盘 / 缺货 / 压货？）用来锚定价值叙事。

## C. 业务规则与口径

- **C1. target_ending_inventory（目标期末库存 / 目标 weeks_of_cover）按什么定？** 全局一个值还是按渠道/SKU 分级？（`05 §1/2`）
- **C2. 缺货/压货的业务阈值？** weeks_of_cover 多少算缺货风险、多少算压货？由谁拍板？
- **C3. 层级口径**：Region/Country/Channel/SKU 的汇总口径是否已对齐？是否存在跨币种/跨口径问题？（`03 §3` / `04` 校准）
- **C4. 哪些 SKU 算"新品"、哪些算"EOL"？** 判定规则。

## D. 成功标准与试点

- 🔴 **D1. 高层认可的 FVA 阈值是多少？**（相对现状 WAPE 改进多少算"值得推广"？）这是 `00 §6` 成功标准的待填项。
- **D2. shadow-mode 试点选哪个国家？谁是友好的早期采用者（本地销售负责人）？**（`01 §3`）
- **D3. 试点运行多久？** 建议 6–8 周，需覆盖至少一次促销，请干系人确认时间窗。

## E. 范围与角色

- **E1. v1 聚焦哪 1 个 Region、哪 2–3 个国家、哪 2–3 个渠道、哪 ~10 个 SKU？**（`08 §2` MVP 范围的待填项）
- **E2. 五个页面里，试点阶段先上哪两个？**（建议 Executive Overview + Workbench）
- **E3. 谁有 override 权限？override_reason 用自由文本还是预设枚举 + 备注？**（`06 §4`）

## F. 工程与合规

- **F1. 数据出口/隐私限制？** 销售数据能否进入 LLM（Agent 层）？是否需要脱敏/本地化部署？这会影响 Agent 选型。
- **F2. 数据如何交付？**（定期导出 CSV/Excel？数据库直连？）决定数据导入层形态。
- **F3. 运行环境？** 是否有 GPU（影响是否、何时引入 Foundation Model）；部署在何处。
